# Marathon The Hague 2026: road closures

One page: the NN Marathon The Hague course on a map, with each of the 19 official road closures coloured by its state right now and a badge with the time left until it reopens. A Runner view shows where a runner can be on the course. After the first visit it works fully offline (service worker, map tiles included). On iPhone, use Share → Add to Home Screen.

Live: https://djosh34.github.io/marathon_den_haag_tracker_2026/

- Closure times come from the official closure map on the [travel info page](https://nnmarathonthehague.nl/en/travel-info/). The course GPX files come from the [course page](https://nnmarathonthehague.nl/en/course/). The times are indicative.
- Tap the clock to look at another time of race day (09:00 to 16:00) with a slider. "Back to live" returns to now.
- Runner: set the start time and the finish window. The orange range on the course runs from the slowest pace (finish until) to the fastest (finish from), at an even pace.

## Code

SvelteKit + Tailwind CSS in TypeScript, built to static files with `@sveltejs/adapter-static`.

- `src/routes/+page.svelte`: the page (clock, time travel, Roads/Runner toggle, bottom sheet).
- `src/lib/map.ts`: MapLibre map, with the WebKit workarounds documented in the comments.
- `src/lib/time.ts`: closure states and colours. `src/lib/runner.ts`: the runner range and pace.
- `src/lib/data.json`: generated by `python3 tools/build_data.py` from the GPX files and the closure list (routes, closures, km markers). Its types are in `src/lib/data.ts`.
- `src/service-worker/`: caches every file at install and serves from the cache only (with its own `tsconfig.json`, as SvelteKit 3 wants).
- `static/`: map tiles (a Protomaps extract, `map/hague.pmtiles`, zoom 0–14), glyphs, sprites, the Overpass font (OFL), icons, manifest.
- Colours live in the Tailwind theme in `src/app.css`.

## Develop

```sh
npm install
npm run dev      # http://localhost:5173
npm run check    # type check (svelte-check, and tsc for the service worker)
npm run build    # static site in build/, served from the root
BASE_PATH=/marathon_den_haag_tracker_2026 npm run build   # as on GitHub Pages
```

Every build is a new version: open phones get a "New version ready. Tap to update." banner.

## Test

```sh
npm run build
python3 -m http.server 8643 --bind 127.0.0.1 -d build &
podman run --rm --network host --ipc host -v "$PWD":/work:Z -w /work \
  mcr.microsoft.com/playwright:v1.64.1-noble node tools/test.ts http://127.0.0.1:8643/
```

The test runs Playwright WebKit with the `iPhone 17 Pro` profile and writes screenshots to `screenshots/svelte/`. It checks the closures at race-day times, the time-travel slider, a closure changing live, the runner view (range, km markers, settings), and an offline reload that must make zero network requests.

## Deploy

`.github/workflows/pages.yml` builds with the Pages base path and deploys with `actions/deploy-pages` on every push to `master`. It needs the repo's Pages source set to "GitHub Actions" (Settings → Pages).
